## 2. Architecture & Mathematical Formulation

### 2.1. Model Backbone (Report 1 §5.1)
- **Encoder:** 2-layer GRU backbone with hidden size $d = 64$.
  - Input: 24 historical hours with 7 features (`energy_scaled`, `hour_sin`, `hour_cos`, `weekday_sin`, `weekday_cos`, `is_weekend`, `energy_present_mask`).
  - Output: Latent representation $z_t \in \mathbb{R}^{64}$ taken from the top GRU layer at the final historical step.
- **Head:** Multi-Layer Perceptron (MLP) mapping concatenated $z_t$ (64 dims) and future 24-hour calendar $c_{\text{future}}$ (24 $\times$ 5 = 120 dims) through hidden layer (128 units) with ReLU activation $\to$ Linear(128, 24) $\to$ **Softplus** activation, enforcing non-negative hourly forecasts.

### 2.2. Loss Functions (Report 1 §5.2–5.4)
- **Forecast Loss:**
  $$L_{\text{forecast}}(t) = \frac{1}{24}\sum_{h=1}^{24} |\hat{y}_{t,h} - y_{t,h}|$$
- **Latent Retention Loss:**
  $$L_{\text{retain}}(t) = \frac{1}{d}\sum_{k=1}^d \left[ \frac{z_{T,k}(X_t) - z_{S,k}(X_t)}{s_k + \epsilon} \right]^2 \quad (d = 64)$$
  - $z_S(X_t)$ is generated by a frozen reference Source Encoder in evaluation mode without gradient propagation.
  - $s_k$ is the per-dimension empirical standard deviation of latent activations across source training data, clamped with $\epsilon = 10^{-5}$.
- **Total Adaptation Loss:**
  $$L_{\text{total}}(t) = L_{\text{forecast}}(t) + \lambda_t L_{\text{retain}}(t)$$
  - $\lambda_t \in \Lambda = \{0, \lambda_{\text{low}}, \lambda_{\text{high}}\}$, with $0 < \lambda_{\text{low}} < \lambda_{\text{high}}$ (e.g. $\lambda_{\text{low}} = 0.1, \lambda_{\text{high}} = 1.0$). $\lambda = 0$ corresponds to unconstrained fine-tuning.

## 3. Confidence-Based Retention Controller (Report 1 §6)

### 3.1. Block Forking & Prequential Protocol
1. **Target Initial Adaptation:** Pretrained source model undergoes initial target adaptation on the permitted history prefix (6 samples for 7d, 13 samples for 14d, 27 samples for 28d) using initial $\lambda = 0.1$.
2. **Block Initialization:** At the start of block $q$ (14 days), the active model weights and optimizer state are cloned identically into 3 candidate branches:
   - Candidate `cand_0`: $\lambda = 0.0$
   - Candidate `cand_low`: $\lambda = 0.1$
   - Candidate `cand_high`: $\lambda = 1.0$
   All 3 candidates share identical input normalization, batch order, and step budget.
3. **Prequential Forecast Issuance:** Predictions $\hat{y}$ for all 3 candidates are generated and stored **prior** to label arrival each day.
4. **Prequential Scoring:** When all 24 hourly labels for day $b$ are complete, daily normalized MAE $\ell_b^c$ is computed for each candidate.
5. **Candidate Update:** Each candidate undergoes independent gradient descent on that day's complete data using its designated $\lambda$.

### 3.2. Statistical Testing & Decision Rules
- **Paired Daily Improvement:** For complete day $b$, the improvement of challenger $j$ over active $a$ is:
  $$d_b^{j,a} = \ell_b^a - \ell_b^j$$
  where $d_b > 0$ indicates lower error (better performance) by the challenger.
- **Day-Block Bootstrap LCB:** Computed over $B$ complete days with $N_{\text{boot}} = 1000$ resamples. The one-sided Lower Confidence Bound (LCB) at level $\alpha = 0.05$ (adjusted to $\alpha / 2 = 0.025$ via Bonferroni for 2 challengers) is:
  $$\text{LCB}_q^{j,a} = \text{quantile}(\text{boot\_means}, \alpha_{\text{eff}})$$
- **Strict Qualification Gate:** A challenger qualifies if and only if:
  $$B \ge B_{\min} \quad \text{and} \quad \text{LCB}_q^{j,a} > \delta \quad (\delta = 0.0)$$
- **Selection & Tie-Breaking:**
  1. If no challenger qualifies $\to$ **KEEP** active.
  2. If multiple challengers qualify $\to$ select largest $\text{LCB}_q^{j,a}$.
  3. If LCB values are tied $\to$ select challenger nearest to current active $\lambda$: $\min |\lambda_j - \lambda_a|$.
  4. If still tied $\to$ select by fixed deterministic order (smaller $\lambda$ first).
- **State Continuity:** Winning candidate's checkpoint and optimizer state are carried forward as active for block $q+1$. Keeping active does **not** reset weights to block start.

## 8. Limitations & Scope Non-Claims

1. **Independent Member Study:** This work fulfills Issue #41 as an independent study. It does not replace the shared production runner (#21) or co-lead deliverables (#39).
2. **Development-Only Evaluation:** Replay was performed exclusively on Development targets (`['urbanev', 'SZH', '1001']`). No final evaluation targets were accessed, filtered, or tuned.
3. **Behavior of Real-Data Transitions:** While synthetic tests guarantee proper switching when evidence is indisputable, real development data exhibited blocks where evidence did not exceed $\delta = 0.0$ (e.g. Block 2 in all budgets, and Blocks 2-3 in 28d), appropriately resulting in `keep` decisions. This behavior confirms that the confidence controller protects against unwarranted parameter churn.
