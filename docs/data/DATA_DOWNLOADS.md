## Install without changing the snapshot

1. Clone/check out the matching reviewed input code. These outputs were generated by runtime commit `a37c345`; [the integration record](../reports/data-integration.md) identifies the combined verification and lead-directed promotion to main. Use the promoted main version after its CI/merge checks, or the exact recorded input runtime for historical reproduction. `docs/reports/input-handoff-evidence.json` records executed source hashes/configs for all 21 runs.
2. Download the needed file from the observed Drive link in the release catalog. Do not use Google Sheets import/conversion for JSONL or CSV data.
3. Verify the downloaded archive's byte size and SHA-256 against the committed [release catalog](../../data/releases/DATA-v1-20261019.json). The same package hashes are in `SHA256SUMS.txt` in the Drive release folder.

   macOS/Linux:

   ```sh
   shasum -a 256 inputs-urbanev-SZH-v1.zip
   ```

   Windows PowerShell:

   ```powershell
   Get-FileHash .\inputs-urbanev-SZH-v1.zip -Algorithm SHA256
   ```

   Compare the complete digest; mismatch means stop, preserve the failed download separately and investigate/re-download. Do not change the expected hash to get PASS.

4. Extract a processed/input ZIP into a **fresh TFL-EV repository root**, not inside another `data/inputs` directory. Every entry already starts with `data/processed/...` or `data/inputs/...`. Do not overwrite an existing run directory; first verify it or use a fresh checkout/storage root.

   ```sh
   python -m zipfile -e /path/to/inputs-urbanev-SZH-v1.zip .
   ```

5. For raw work, place the two original ZIPs unchanged at:

   ```text
   data/raw/urbanev/official_2026_05_11/UrbanEVDataset.zip
   data/raw/charged/zenodo_15814263/Hourly.zip
   ```

   Then use `python -m tools.sources verify --dataset urbanev` or `--dataset charged`. Do not extract raw archives into the prepared input directories.

6. Check the installed input `manifest.json`: `missing_data_policy` must be `ev-missing-data-v1` and schema `ev-loader-run-v2`. UrbanEV records explicit coverage limits; that status is expected and is not permission to silently discard blocked/skipped cases. Use the manifest's artifact hashes and the consumer verification in `iter_forecasts`.

Absolute source paths inside retained manifests describe the original producer machine; do not edit them merely to consume the snapshot. `iter_forecasts` reads the installed run and its relative artifact paths using the recorded manifest fingerprint. Reprocessing on a different machine needs a new config/run with that machine's producer path.

Data installs under the existing ignored folders. Do not commit downloaded ZIPs, extracted datasets, environments or checkpoints to Git. A full set of compressed input ZIPs is about 637 MB; allow over 10 GB for extracted input artifacts. Raw/processed download and extraction require additional space.

## Verification and acceptance boundary

Before packaging, all included producer/input artifacts were freshly checked against their manifests. All nine new ZIPs passed CRC inspection; package SHA-256 values are recorded. Both original raw archives were freshly verified against the source catalog without mutation. Drive upload completion, byte sizes, parent folders and public-reader permissions are checked separately; downloading team members must verify SHA-256 locally. Do not describe metadata readback alone as a remote-byte SHA-256 verification.

The release is a fixed data snapshot, not a new scientific acceptance claim. Clock/arrival assumptions, ID-level co-location dependence, CHARGED upstream preprocessing and SZH overlap limits remain documented. Raw/source terms remain those of the original publishers. The integration report records subsequent lead acceptance, promotion and issue disposition. The release catalog retains its publication-time pending-review wording as immutable provenance; uploading data alone did not authorize acceptance. New artifacts or policy changes require a new release version rather than replacing these files.
