# CHARGED dataset reference — AMS

## 1. Source, scope, and provider processing

CHARGED is a multi-city dataset for EV charging-demand analysis, introduced in Scientific Data in 2025. The paper reports 11,953 chargers grouped into 4,280 virtual sites across Amsterdam (AMS), Johannesburg (JHB), Los Angeles (LOA), Melbourne (MEL), São Paulo (SPO), and Shenzhen (SZH), covering April–September 2023. These global counts are publisher claims; the detailed file explanations here cover AMS. The separate [six-city inventory](../reports/charged-inventory.md) records actual standard-release file counts, schemas, clocks, missing values and zeros for Issue #17 Step 1. It does not approve cities for forecasting.

**CHARGED Hourly is already processed by its provider.** The provider describes parsing plug-level states/power, filtering, outlier treatment, interpolation/filling, spatial clustering, and hourly aggregation. Storing the unchanged archive under `data/raw/` means it is a preserved project input; it does not mean untouched observations or direct meter readings. Our processing and model-input pipelines are not implemented by this document.

Sources: [paper](https://doi.org/10.1038/s41597-025-05584-7), [release](https://zenodo.org/records/15814263), and [source catalog](../../data/sources.json). Acquisition evidence: [report](../reports/data-acquisition.md).

The acquired `Hourly.zip` is 268,720,500 bytes. Its SHA-256 and publisher MD5 matched the recorded catalog. It contains 120 CSVs: ten files in each of six standard city directories and six corresponding `*_remove_zero` directories. Only standard directories are retained as extracted copies; both variants remain in the immutable ZIP. No automatic cohort selection is implied.

```text
Hourly.zip
├── AMS/                         # ten files, listed below
├── JHB/  LOA/  MEL/  SPO/  SZH/ # standard versions
└── *_remove_zero/               # provider-filtered alternatives, not selected

AMS/
├── info.csv
├── sites.csv
├── chargers.csv
├── distance.csv
├── duration.csv
├── volume.csv
├── e_price.csv
├── s_price.csv
├── weather.csv
└── poi.csv
```

A **site** is a spatial cluster generated by the provider, not necessarily a physical charging facility. A charger belongs to a site and may have multiple plugs. The released metadata does not enumerate plug counts.

AMS contains 2,449 sites and 3,526 chargers: 1,738 sites have one charger and 711 have multiple chargers; the largest has 16. A singleton site does not establish residential/private charging.

The [publisher preprocessing and AMS semantics audit](../reports/charged-preprocessing.md) distinguishes paper statements, pinned public code and direct release observations. It documents upstream imputation risks without asserting strict-online readiness or excluding sites.

The [forecasting-suitability and Shenzhen/UrbanEV overlap assessment](../reports/charged-suitability.md) proposes bounded benchmark claims and documents extensive exact-coordinate overlap. It is a review proposal, not an accepted input pipeline.

## 2. Reading the examples

Tables below come directly from the local standard AMS CSVs. Headers, order and value strings are preserved. Blank header cells match the CSV. Wide matrices show only their first three data columns; static examples select a few identified rows. Decimal points match the files. Calculations and rounded explanations are separate from source values.

IDs have no physical units. Join using city plus site ID across cities, and explicit IDs within a city; never infer membership from row position or identifier digits.

## 13. Verification, time semantics, and unresolved limits

Direct numerical inspection is scoped to AMS. Evidence and input hashes are in [charged-ams-verification.json](../reports/charged-ams-verification.json). No raw data was modified. Checks used upstream commit `ff13cefe0c9e15073d02ad1e57efb4054dd70c5a`.

### Verified relationships

- Every site's member count matches charger_num.
- Site coordinates match the mean charger coordinates.
- Static site duration/volume totals match sums over member chargers; city static totals agree with those metadata sums.
- Site avg_power matches the arithmetic mean of member charger avg_power at all 2,449 sites. The city value matches the arithmetic mean across 3,526 chargers. This is a matching numerical formula, not proof of the original generator. The original per-charger averaging procedure was not found in the inspected sources.
- Buffered geometry was reconstructed for all sites; maximum absolute errors were about 3.82e-9 projected m in perimeter and 1.18e-7 projected m² in area.
- Each hourly duration/volume table has 10,756,008 value cells, without blank, nonfinite, or negative values. Completeness after processing is not evidence of complete original observations.

### Time interpretation

Both charging series have 4,392 distinct hourly timestamps from 2023-04-01 00:00:00 to 2023-09-30 23:00:00, without gaps. Column order starts 0, 1, 10, 100, etc., consistent with string sorting; join by labels rather than numeric position.

The public aggregation script applies floor('H'), consistent with start-labeled bins [t, t+1h). It has placeholder paths and a full-year 2023 filter, so it does not establish the exact released archive build. The paper describes local city time; every AMS timestamp in this six-month window would be UTC+2 under Europe/Amsterdam. No DST transition occurs inside this window. The CSV itself has no timezone offset, and original collection/conversion logs are unavailable.

### Static versus hourly totals

| Quantity | Sum of static sites.csv | Sum of released hourly series |
|---|---:|---:|
| Duration (documented h) | 28808415.08728028 | 18388657.432718504 |
| Volume (kWh) | 239175391.2915903 | 149692010.34636593 |

Both comparisons differ at 1,388 active sites. For site 8, static duration is approximately 75,826.67 versus hourly sum 43,442.67; static energy is approximately 485,290.67 versus hourly sum 278,033.07. The cause is unresolved; do not assert a different period, a correction stage, or an export bug without evidence. Do not present metadata totals as sums of the released hourly series.

Site 8 has one charger but hourly duration reaches 14.666666666666666 documented h. Multiple plugs mean a one-hour-per-charger limit is not generally valid, but missing plug counts/state histories prevent validating this value physically. Do not silently divide by 60, clip, or alter labels.

### Processing and provenance limits

The publisher interpolates/fills records. Public aggregation code also fills missing pivot entries with zero. The acquired archive contains no separate observation/imputation mask file; original observation status cannot be recovered per cell from this release alone. Zero does not automatically establish inactivity, free charging, or a missing record. Published interpolation may involve future observations; causal/online suitability is not established.

Unresolved items: original per-charger avg_power generation; static/hourly discrepancy; plug-level duration reconstruction; exact released build and collection timestamps; AMS price currency; snow-unit conversion. Keep these limitations visible rather than modifying inputs to hide them.

## 14. Research use and next handoff

Understanding these ten files does not complete data QC or model inputs. Provider processing does not remove the need to verify CHARGED's suitability for the agreed protocol. No city/cohort, auxiliary feature, or cross-city transfer protocol is selected here. Shenzhen independence from UrbanEV remains unverified.
